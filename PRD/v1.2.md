## Version 1.2 — Eternals Radiance tab (2026-06-12)

Added `ETERNALS_DATA.radiance` as a sibling of `ETERNALS_DATA.materials` in `supplies-eternals.js`, with two new element groups (`enneadomegaanima`, `omega3omegaanima`) and new items including `immortalfragment` and `terraadamant`. `CalcEternal.vue` gained a tab switcher rendering a second `<Calculator>` instance bound to `ETERNALS_DATA.radiance` and the `CalcEternal-radianceProgress` localStorage key; the existing recruit/transcend tab is unchanged. Element assignment in the new groups is positional (fire…dark). 14 new icons fetched into `public/img/item/` via WikiParser. `Calculator.vue` was not modified.

## Version 1.2.2 — Radiance reduce step corrected (2026-06-14)

The Radiance step "Reduce Revenant Weapon" had an incorrect quantity inherited from the recruit/transcend data. Corrected from 10 to **4 weapons** (`×0.4` scaling across all quantities in that step). Recruit/transcend reduce steps remain untouched.

## Version 1.2.3 — Item-image manifest + build-time check (2026-06-14)

Added `WikiParser/data/supplies.images` — a `URL⇥<key>.jpg` manifest (one line per static item, no blank/comment lines; folded in the previously separate `radiance.images` and deleted it). Added `scripts/check-item-images.js` which asserts that every item in `supplies.js` has a matching icon in `public/img/item/<key>.<jpg|gif>`; wired as npm `test` (direct run) and `prebuild` (before every build) so a missing icon fails the build. A committed `.githooks/pre-commit` (via the `prepare` install hook) runs `npm test` before every commit; bypassable with `--no-verify` — `prebuild`/CI is the hard gate. Reintroduced a browser `favicon.svg` (`faBook` glyph), **superseding the v1.1 no-favicon decision**.

## Version 1.2.4 — CDN image source, homepage lettering & icon refresh (2026-06-14)

Added an optional `itemId` field to the `supplies.js` `Item` class and populated it for the **282** item-path items plus the **30** weapon-namespace items (their weapon id, resolved on the CDN **weapon path** `.../assets/weapon/s/<itemId>.jpg`, not `item/article/s/`); only the **4** animated `.gif` items carry none. ## Version 1.2.6 — Static SEO / social-preview meta (2026-06-14)

Added static `<head>` tags to `index.html` — `<link rel="canonical">`, Open Graph (`og:type=website`, `og:url/title/description/image` + `og:image:width/height`), and Twitter Card (`summary_large_image`) — all hardcoding the absolute production origin `https://rene880.github.io/raziel-ledger/` (a subpath base makes relative OG URLs unreliable, and scrapers don't run JS). Added the hand-authored `public/img/og-preview.png` (1200×630, "Raziel Ledger" in Great Vibes on the dark theme, rendered with PIL from the upstream TTF) — not a game asset, outside `check-item-images.js`. Replaced the `cp dist/index.html dist/404.html` deep-link step with a dedicated rafgraph `public/404.html` redirect (`?/<path>`, `pathSegmentsToKeep=1`) plus the matching decode snippet in `index.html`, so deep links resolve to a 200 home document with the URL normalized before the router boots (the first GitHub response for an unknown path is still 404 — a Pages limitation). `robots.txt`/`sitemap.xml` deliberately omitted (subpath files aren't auto-discovered). Bumped to 1.2.6.

## Version 1.2.8 — Per-route titles/meta + sitemap (2026-06-14)

Gave each route in `src/router/index.js` a `meta: { title, description }` (Home / Eternals / Evokers / NotFound) and added a `router.afterEach` hook that sets `document.title` and updates the in-document `<meta name="title|description">`, `<link rel="canonical">`, and `og:`/`twitter:` title/description/url per route (canonical/og `url` = absolute production URL; missing tags skipped). This **replaced** the per-page `setHead()` mechanism — removed the `mounted()` `setHead()` calls from all four pages and deleted `src/js/head.js` (previously `mounted()` ran after `afterEach` and silently overrode the route-meta title). Added `public/sitemap.xml` (the three real routes, absolute `loc`s; copied to `dist/sitemap.xml`) for **manual** Google Search Console submission — partially reversing 1.2.6's "no sitemap" decision (still true for *auto-discovery*; a subpath sitemap isn't crawled unprompted). No new dependency (the hook mutates pre-existing DOM tags); static `index.html` tags stay authoritative for no-JS scrapers, the hook benefits the tab title + Googlebot. `sitemap.xml` is not a game asset (outside `check-item-images.js`).

## Version 1.2.9 — Per-route static social previews (build-time pre-render) (2026-06-14)

### Problem

`/calceternal` and `/calcevoker` unfurl with **no** link-preview card when shared (Discord, X, Slack, Facebook, iMessage), while the root `/` does show one. The cause is the interaction of two earlier decisions:

- **The deep routes are served from GitHub's `404.html`** (v1.2.6). A scraper requesting `https://rene880.github.io/raziel-ledger/calceternal` gets GitHub Pages' `404.html` — which carries **no** Open Graph / Twitter tags, only a rafgraph redirect script. Scrapers don't run JS, so the redirect never fires and there is nothing to unfurl. Only `/` resolves to the real `index.html`.
- **The 1.2.8 `afterEach` hook is JS-only**. It updates per-route meta at runtime, which Googlebot and the browser tab see, but link-preview crawlers never execute it.

SSR remains out of scope. The fix is **build-time pre-rendering**: emit a real static HTML file per route so GitHub Pages serves a 200 document with route-specific static tags — no server needed.

### Scope

| # | Change |
|---|--------|
| S1 | Extract the route SEO metadata out of `src/router/index.js` into a shared, dependency-free module `src/seo/meta.js`: `SITE_ORIGIN`, `SITE_NAME`, `DEFAULT_TITLE`, `DEFAULT_DESCRIPTION`, `OG_IMAGE`, and a `ROUTES` table of `{ path, title, description }` for Home / `/calceternal` / `/calcevoker` / NotFound. `router/index.js` imports from it and keeps its `afterEach` hook unchanged — single source of truth shared with the pre-render script. |
| S2 | Add `scripts/prerender-routes.js`, run as a new `postbuild` npm script (after `vite build`). It reads the built `dist/index.html` and, for `/calceternal` and `/calcevoker`, writes `dist/<route>/index.html` with that route's static tags swapped in: `<title>`, `<meta name="title">`, `<meta name="description">`, `<link rel="canonical">`, `og:title`/`og:description`/`og:url`, and `twitter:title`/`twitter:description`. Plain string/regex replacement on the built HTML — no new dependency. |
| S3 | The OG/Twitter **image** stays the single sitewide `public/img/og-preview.png` (resolved decision — only title/description/url differ per route). `og:type`, `og:image:width/height`, `twitter:card`, the rafgraph decode snippet, and the hashed asset references are copied through unchanged. |
| S4 | Result: `/calceternal` and `/calcevoker` now serve a real **200** HTML file with correct static tags directly from GitHub Pages; they no longer fall through to `404.html`. The rafgraph `404.html` redirect (v1.2.6) remains in place for genuinely unknown paths (→ NotFound). |
| S5 | Bump `package.json` `version` to **1.2.9**; sync `CLAUDE.md` and `README.md`. |

### Notes & constraints

- **No new dependency, no SSR.** The script is plain Node doing text substitution on the built `index.html`; it imports the same `src/seo/meta.js` the router uses, so titles can never drift.
- **Static tags are now per-route, not sitewide.** `/calceternal` and `/calcevoker` now have their own static cards; the 1.2.8 `afterEach` hook remains useful for the browser tab + Googlebot.
- **Only the three real routes are pre-rendered.** NotFound is intentionally left to the `404.html` path.
- `og-preview.png` is hand-authored art, not a game asset; `check-item-images.js` is unaffected.
- `package.json` version stays the single source of truth.

### Acceptance criteria

1. After `npm run build`, `dist/calceternal/index.html` and `dist/calcevoker/index.html` exist, each with its own `<title>`, `og:title`, `og:description`, and `og:url`.
2. Pasting `https://rene880.github.io/raziel-ledger/calceternal` (and `…/calcevoker`) into a link-preview validator renders a card with the page-specific title and description; the root `/` card is unchanged.
3. Loading both deep links in `npm run preview` hydrates the SPA and routes to the correct calculator with the clean URL (no `?/` redirect needed for these two paths).
4. `npm test` still passes (316 item icons).
5. `package.json` `version` is `1.2.9`; `CLAUDE.md` and `README.md` reflect v1.2.9.

## Version 1.2.10 — Self-hosted subsetted homepage font (2026-06-14)

### Problem

The homepage hero ("Raziel Ledger" in Great Vibes, `Home.vue`) loaded the font from Google Fonts via a render-blocking cross-origin chain in `index.html`:

```
HTML → fonts.googleapis.com/css2 (~151 ms) → fonts.gstatic.com woff2 (~1,296 ms, 29.70 KiB)
```

The ~1.3 s is dominated by a **second** origin's DNS + TLS handshake, not transfer — and the full Latin charset is shipped when the hero needs only **11 glyphs** (`R a z i e l L d g r` + space). Great Vibes is used nowhere else at runtime.

### Scope

| # | Change |
|---|--------|
| S1 | Add `public/fonts/great-vibes-subset.woff2` — Great Vibes (OFL) subset to the 11 hero glyphs (~6 KB, down from 29.70 KiB). Obtained from the Google Fonts `&text=Raziel Ledger` endpoint. Not a game asset — outside `check-item-images.js`. |
| S2 | In `index.html`, replace the two `preconnect`s + the css2 `<link rel="stylesheet">` with a same-origin `@font-face` (inline `<style>`, `font-display: swap`) and a `<link rel="preload" as="font" type="font/woff2" crossorigin>`, both pointing at `%BASE_URL%fonts/great-vibes-subset.woff2`. |
| S3 | In `scripts/prerender-routes.js`, strip the font `preload` from the calc-route pre-renders (the hero font isn't used on `/calceternal` or `/calcevoker`) so they don't fetch an unused font. The inert `@font-face` is left in place. |
| S4 | Bump `package.json` `version` to **1.2.10**; sync `CLAUDE.md` and `README.md`. |

### Notes & constraints

- **No Google Fonts request at runtime.** The font is served same-origin from GitHub Pages, eliminating the cross-origin DNS/TLS chain (~1.3 s).
- **OFL licensing.** Great Vibes is SIL Open Font License; self-hosting/subsetting is permitted.
- `Home.vue`'s `font-family: 'Great Vibes', …` is unchanged — it now resolves against the self-hosted `@font-face`.
- The standalone `public/img/raziel-ledger-lettering.svg` still carries its own (now unused) Google Fonts `@import`; it is not loaded by the app and is left as-is.
- `og-preview.png` and the lettering SVG remain hand-authored, not game assets.

### Acceptance criteria

1. `public/fonts/great-vibes-subset.woff2` exists (~6 KB, valid WOFF2) and deploys to `https://rene880.github.io/raziel-ledger/fonts/great-vibes-subset.woff2`.
2. `index.html` contains no `fonts.googleapis.com` / `fonts.gstatic.com` references; the hero renders in Great Vibes from the self-hosted font with no Google network request.
3. After `npm run build`, `dist/index.html` preloads the font; the pre-rendered `dist/calceternal/index.html` and `dist/calcevoker/index.html` keep the `@font-face` but **not** the preload.
4. `npm test` still passes (316 item icons).
5. `package.json` `version` is `1.2.10`; `CLAUDE.md` and `README.md` reflect v1.2.10.
